# A33 Group

This is the group of APIs between
the [Partner's Knowledge Update Service](../services/partner/S12_Partner_Knowledge_Update_Service.md)
and [Partner's Local Knowledge Service](../services/partner/S11_Partner_Local_Knowledge_Service.md).

This API consists of 1 API.

## A33

This API is based on RabbitMQ.

The API has 1 method.

### A33 Method: `update_local_knowledge`

Request body format:

```json
{
  "method": "update_local_knowledge",
  "params": {
    "source": "Viettel",
    "update_type": "full_replace",
    "data": [
      {
        "Mã dịch vụ": "SD70",
        "Thời gian thanh toán": "Trả trước",
        "Các dịch vụ tiên quyết": "",
        "Giá (VNĐ)": 70000,
        "Chu kỳ (ngày)": 30,
        "4G tốc độ tiêu chuẩn/ngày": 1,
        "4G tốc độ cao/ngày": 0,
        "4G tốc độ tiêu chuẩn/chu kỳ": 30,
        "4G tốc độ cao/chu kỳ": 0,
        "Gọi nội mạng": "",
        "Gọi ngoại mạng": "",
        "Tin nhắn": "",
        "Chi tiết": "",
        "Tự động gia hạn": "Có",
        "Cú pháp đăng ký": "SD70 DK8 gửi 290"
      }
    ],
    "partner_id": "viettel-hcm-001",
    "sync_timestamp": "2024-01-15T10:30:00Z"
  },
  "id": "update-1234"
}
```

Response body format:

```json
{
    "id": "the corresponding request id",
    "result": {
        "status": "success or error",
        "content": {
            "records_processed": 150,
            "records_added": 120,
            "records_updated": 25,
            "records_deleted": 5,
            "processing_time_ms": 2340,
            "storage_size_mb": 15.7
        }
    }
}
```

On success, the content includes:
- `records_processed`: Total number of records in the update
- `records_added`: Number of new records added
- `records_updated`: Number of existing records updated
- `records_deleted`: Number of records removed (for full_replace mode)
- `processing_time_ms`: Time taken to process the update
- `storage_size_mb`: Current size of the local knowledge base

On failure (`status == 'error'`), the content would
reflect what is going on. If the failure is
caused by some `Exception`, the content should
be `str(e)` with `e` being the `Exception` instance
that was the culprit.

In special error cases, the content must be:
- `"INVALID_UPDATE_TYPE"` - If update_type is not recognized (valid: "full_replace", "incremental", "merge")
- `"STORAGE_FULL"` - If local storage capacity is exceeded
- `"CORRUPTED_DATA"` - If the data payload is corrupted or cannot be processed
- `"SYNC_CONFLICT"` - If sync_timestamp indicates data is older than current local version

## Update Types

- `full_replace`: Completely replaces all knowledge from the specified source
- `incremental`: Adds new records and updates existing ones, doesn't delete
- `merge`: Intelligently merges changes, preserving local modifications where appropriate

## Queue Configuration

Default queue names (configurable via `.env`):
- Request Queue: `partner_knowledge_update_requests`
- Response Queue: `partner_knowledge_update_responses`
