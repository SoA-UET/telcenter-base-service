# A08 Group

This is the group of APIs between
various Core/Partner services and [Core's Knowledge Service](../services/core/S03_Knowledge_Service.md) or [Core's Metrics Service](../services/core/S08_Metrics_Service.md).

This API consists of 2 methods.

## A08

This API is based on RabbitMQ.

The API has 2 methods.

### A08 Method: `query_knowledge`

Request body format:

```json
{
  "method": "query_knowledge",
  "params": {
    "query": "Gói cước 4G Viettel giá rẻ",
    "source": "Viettel",
    "max_results": 10,
    "filters": {
      "max_price": 200000,
      "min_data_per_day": 1
    }
  },
  "id": "query-5678"
}
```

Response body format:

```json
{
    "id": "the corresponding request id",
    "result": {
        "status": "success or error",
        "content": {
            "results": [
                {
                    "Mã dịch vụ": "ST70",
                    "Giá (VNĐ)": 70000,
                    "4G tốc độ tiêu chuẩn/ngày": 2,
                    "Cú pháp đăng ký": "ST70 gửi 191",
                    "relevance_score": 0.95
                }
            ],
            "total_results": 1
        }
    }
}
```

### A08 Method: `report_metrics`

Request body format:

```json
{
  "method": "report_metrics",
  "params": {
    "service_name": "S03_Knowledge_Service",
    "metric_type": "knowledge_update",
    "timestamp": "2024-01-15T10:30:00Z",
    "metrics": {
      "operation": "update_dataframe",
      "source": "Viettel",
      "records_processed": 150,
      "processing_time_ms": 1250,
      "success": true,
      "validation_score": 0.95,
      "duplicate_count": 2
    },
    "metadata": {
      "request_id": "req-1234",
      "user_id": "system",
      "environment": "production"
    }
  },
  "id": "metrics-1234"
}
```

Response body format:

```json
{
    "id": "the corresponding request id",
    "result": {
        "status": "success or error",
        "content": "OK"
    }
}
```

On success, the content would simply be `OK`. The metrics are stored asynchronously and no additional information is returned.

On failure (`status == 'error'`), the content would
reflect what is going on. If the failure is
caused by some `Exception`, the content should
be `str(e)` with `e` being the `Exception` instance
that was the culprit.

In special error cases, the content must be:
- `"INVALID_METRIC_TYPE"` - If the metric_type is not recognized
- `"MISSING_REQUIRED_FIELDS"` - If required fields are missing from the metrics payload
- `"METRICS_STORAGE_FAILED"` - If storing metrics to database fails

## Supported Metric Types

- `knowledge_update` - Knowledge database updates
- `knowledge_query` - Knowledge queries and retrieval
- `validation` - Knowledge validation operations
- `api_call` - API call metrics (latency, errors)
- `user_interaction` - User interaction metrics

## Queue Configuration

Default queue names (configurable via `.env`):
- Request Queue: `telcenter_metrics_requests`
- Response Queue: `telcenter_metrics_responses`
