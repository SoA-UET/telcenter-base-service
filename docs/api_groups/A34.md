# A34 Group

This is the group of APIs between
various Partner services and [Partner's Metrics Service](../services/partner/S14_Metrics_Service.md).

This API consists of 1 API.

## A34

This API is based on RabbitMQ.

The API has 1 method.

### A34 Method: `report_partner_metrics`

Request body format:

```json
{
  "method": "report_partner_metrics",
  "params": {
    "partner_id": "viettel-hcm-001",
    "service_name": "S11_Partner_Local_Knowledge_Service",
    "metric_type": "knowledge_query",
    "timestamp": "2024-01-15T10:30:00Z",
    "metrics": {
      "operation": "query_knowledge",
      "query_count": 1,
      "results_returned": 5,
      "query_time_ms": 85,
      "cache_hit": false,
      "success": true
    },
    "metadata": {
      "request_id": "query-1234",
      "consultant_id": "consultant-456",
      "session_id": "session-789"
    }
  },
  "id": "partner-metrics-1234"
}
```

Response body format:

```json
{
    "id": "the corresponding request id",
    "result": {
        "status": "success or error",
        "content": "OK"
    }
}
```

On success, the content would simply be `OK`. The metrics are stored asynchronously and no additional information is returned.

On failure (`status == 'error'`), the content would
reflect what is going on. If the failure is
caused by some `Exception`, the content should
be `str(e)` with `e` being the `Exception` instance
that was the culprit.

In special error cases, the content must be:
- `"INVALID_PARTNER_ID"` - If the partner_id is not recognized
- `"INVALID_METRIC_TYPE"` - If the metric_type is not recognized
- `"MISSING_REQUIRED_FIELDS"` - If required fields are missing
- `"METRICS_STORAGE_FAILED"` - If storing metrics fails

## Supported Metric Types

- `knowledge_query` - Knowledge queries performed by consultants
- `knowledge_update` - Knowledge base synchronization updates
- `file_import` - File import operations and statistics
- `consultation_session` - Consultant session metrics
- `system_health` - System health and resource usage metrics

## Queue Configuration

Default queue names (configurable via `.env`):
- Request Queue: `partner_metrics_requests`
- Response Queue: `partner_metrics_responses`
