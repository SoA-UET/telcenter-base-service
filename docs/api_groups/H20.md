# H20 Group

## Overview

This is the group of HTTP APIs between the **Customer Web / End User Client**
and [**Customer Identity Service – S04**](../services/core/S04_Customer_Identity_Service.md).

This API group supports:

* **UC-01: User Registration**
* **UC-02: User Login**
* **UC-02a: OAuth Login**

The APIs are designed following RESTful principles and focus only on **account creation and authentication** for end users.

---

## Endpoints

| No | Endpoint                          | Method | Use Case | Description          |
| -- | --------------------------------- | ------ | -------- | -------------------- |
| 1  | `/api/v1/auth/register`           | POST   | UC-01    | User registration    |
| 2  | `/api/v1/auth/login`              | POST   | UC-02    | User login           |
| 2a | `/api/v1/auth/oauth/login`        | GET    | UC-02a   | OAuth login redirect |
| 2b | `/api/v1/auth/oauth/callback`     | GET    | UC-02a   | OAuth callback       |

#### POST /api/v1/auth/register

(**UC-01 – User Registration**)

This endpoint allows an End User to create a new customer account in the system.

### Actor

End User

### Preconditions

* The user does **not** have an existing account.

### Postconditions

* A new customer account is created successfully.
* The user can log in immediately after registration.

### Request

**Headers**

* Content-Type: application/json

**Body**

```json
{
  "email": "example@gmail.com",
  "password": "P@ssw0rd123",
  "full_name": "Nguyễn Văn A",
  "address": "TP. Hồ Chí Minh"
}
```

### Behavior

1. The system validates all input fields using regex rules.
2. The system checks whether the email number already exists.
3. If validation passes, a new customer account is created in the **customers** table of the Identity database.
4. The password is securely hashed (BCrypt/Argon2).
5. The system saves the created time and default account status.
6. The system returns the created account information.

### Response (HTTP 201 Created)

```json
{
  "status": "success",
  "customer_id": 10001,
  "message": "Tài khoản được tạo thành công"
}
```

### Alternative Flow

* If the input data is invalid (regex mismatch) **or** the email number already exists:

  * The system returns a validation error.
  * The user must re-enter the registration information.

### Error Responses

* **HTTP 400 Bad Request** – Invalid registration data

```json
{
  "status": "error",
  "error_code": "INVALID_INPUT",
  "message": "Thông tin đăng ký không hợp lệ"
}
```

* **HTTP 409 Conflict** – email number already exists

```json
{
  "status": "error",
  "error_code": "EMAIL_ALREADY_EXISTS",
  "message": "Số điện thoại đã được đăng ký"
}
```

### POST /api/v1/auth/login

(**UC-02 – User Login**)

This endpoint allows an End User to authenticate using an existing account.

### Actor

End User

### Preconditions

* The user already has a registered account.
* The login screen is displayed.

### Postconditions

* If authentication is successful, the system changes to the logged-in state.
* The user is granted access to authorized features.

### Request

**Headers**

* Content-Type: application/json

**Body**

```json
{
  "email": "example@gmail.com",
  "password": "P@ssw0rd123"
}
```

### Behavior

1. The system verifies the email number and password.
2. The system compares the password with the stored password hash.
3. If authentication is successful:

   * A JWT access token is generated.
   * The system returns authentication information.
4. The user is switched to the authenticated state.

### Response (HTTP 200 OK)

```json
{
  "status": "success",
  "message": "Đăng nhập thành công",
  "access_token": "<jwt_token>",
  "token_type": "Bearer",
  "expires_in": 3600,
  "customer": {
    "customer_id": 10001,
    "email": "example@gmail.com",
    "full_name": "Nguyễn Văn A",
    "status": "ACTIVE"
  }
}
```

### Alternative Flow

* If the email number or password is incorrect:

  * The system displays an error message.
  * The user can retry login or exit.

### Error Responses

* **HTTP 400 Bad Request** – Missing credentials

```json
{
  "status": "error",
  "error_code": "MISSING_CREDENTIALS",
  "message": "Vui lòng nhập số điện thoại và mật khẩu"
}
```

* **HTTP 401 Unauthorized** – Invalid credentials

```json
{
  "status": "error",
  "error_code": "INVALID_CREDENTIALS",
  "message": "Số điện thoại hoặc mật khẩu không đúng"
}
```

* **HTTP 403 Forbidden** – Inactive account

```json
{
  "status": "error",
  "error_code": "ACCOUNT_INACTIVE",
  "message": "Tài khoản chưa được kích hoạt hoặc đã bị khóa"
}
```

### GET /api/v1/auth/oauth/login

(**UC-02a – OAuth Login Redirect**)

This endpoint initiates OAuth login for End Users.

### Actor

End User

### Preconditions

* OAuth provider configured (e.g., Google, Facebook).

### Request

**Query Params**

```
provider=google
```

### Behavior

1. Redirect to OAuth provider's authorization URL.
2. User authenticates on provider.
3. Provider redirects back to callback.

### Response (HTTP 302 Redirect)

Redirects to OAuth provider.

---

### GET /api/v1/auth/oauth/callback

(**UC-02a – OAuth Callback**)

This endpoint handles OAuth callback and issues JWT.

### Actor

OAuth Provider

### Preconditions

* User authenticated via provider.

### Request

**Query Params**

```
code=<authorization_code>&state=<state>
```

### Behavior

1. Exchange code for access token from provider.
2. Fetch user info (e.g., email, name).
3. Match or create customer account.
4. Issue JWT.

### Response (HTTP 200 OK)

```json
{
  "status": "success",
  "message": "Đăng nhập OAuth thành công",
  "access_token": "<jwt_token>",
  "token_type": "Bearer",
  "expires_in": 3600,
  "customer": {
    "customer_id": 10001,
    "email": "example@gmail.com",
    "full_name": "Nguyễn Văn A",
    "status": "ACTIVE"
  }
}
```

### Error Responses

* **HTTP 400 Bad Request – Invalid OAuth code**

```json
{
  "status": "error",
  "error_code": "OAUTH_INVALID_CODE",
  "message": "Mã OAuth không hợp lệ"
}
```

## Notes

* All requests and responses use **JSON** format.
* Passwords are stored using **secure hashing (BCrypt/Argon2)**.
* **email number must be unique** in the system.
* Regex validation applies to:

  * email number format
  * Password strength
* **JWT tokens** are required for all authenticated requests and MUST be signed using the RS256 algorithm. Valid tokens MUST be generated in accordance with [the JWT signing workflow](../auth/SIGN.md).
* Registration and login do **not** require authentication.
* Login is required before accessing any protected customer services.
* Currently, only Google OAuth is supported.
* For OAuth login, if the user doesn't have an account, a new customer account may be created based on provider info.
