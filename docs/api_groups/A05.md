# A05 Group

This is the group of APIs between
the [Core's Knowledge Service](../services/core/S03_Knowledge_Service.md)
and [Core's Knowledge Validator Service](../services/core/S05_Knowledge_Validator_Service.md).

This API consists of 1 API.

## A05

This API is based on RabbitMQ.

The API has 1 method.

### A05 Method: `validate_knowledge`

Request body format:

```json
{
  "method": "validate_knowledge",
  "params": {
    "source": "Viettel",
    "data": [
      {
        "Mã dịch vụ": "SD70",
        "Thời gian thanh toán": "Trả trước",
        "Các dịch vụ tiên quyết": "",
        "Giá (VNĐ)": 70000,
        "Chu kỳ (ngày)": 30,
        "4G tốc độ tiêu chuẩn/ngày": 1,
        "4G tốc độ cao/ngày": 0,
        "4G tốc độ tiêu chuẩn/chu kỳ": 30,
        "4G tốc độ cao/chu kỳ": 0,
        "Gọi nội mạng": "",
        "Gọi ngoại mạng": "",
        "Tin nhắn": "",
        "Chi tiết": "",
        "Tự động gia hạn": "Có",
        "Cú pháp đăng ký": "SD70 DK8 gửi 290"
      }
    ],
    "validation_rules": {
      "require_service_code": true,
      "require_pricing": true,
      "allow_duplicates": false
    }
  },
  "id": "validation-req-1234"
}
```

Response body format:

```json
{
    "id": "the corresponding request id",
    "result": {
        "status": "success or error",
        "content": {
            "validation_status": "approved or rejected",
            "quality_score": 0.95,
            "issues": [],
            "warnings": [
                "Service SD70: Missing detailed description"
            ],
            "duplicate_check": {
                "has_duplicates": false,
                "similar_services": []
            }
        }
    }
}
```

On success (`validation_status == "approved"`), the content includes:
- `validation_status`: "approved"
- `quality_score`: A float between 0 and 1 indicating data quality
- `issues`: Empty array
- `warnings`: Array of non-critical issues
- `duplicate_check`: Information about similar existing services

On rejection (`validation_status == "rejected"`), the content includes:
- `validation_status`: "rejected"
- `quality_score`: Lower score indicating poor quality
- `issues`: Array of critical validation errors that caused rejection
- `warnings`: Array of additional warnings
- `duplicate_check`: Information about conflicts with existing data

On failure (`status == 'error'`), the content would
reflect what is going on. If the failure is
caused by some `Exception`, the content should
be `str(e)` with `e` being the `Exception` instance
that was the culprit.

In special error cases, the content must be:
- `"INVALID_SCHEMA"` - If the data does not match the expected schema
- `"INVALID_BUSINESS_RULES"` - If business rule validation fails
- `"VALIDATION_SERVICE_UNAVAILABLE"` - If the validation service itself encounters an error

## Queue Configuration

Default queue names (configurable via `.env`):
- Request Queue: `telcenter_knowledge_validation_requests`
- Response Queue: `telcenter_knowledge_validation_responses`
